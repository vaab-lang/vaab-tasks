# Vaab Tasks

A minimal task list that uses **Vaab as the backend**, with **casts** and **local riffs**:

| Need | Vaab surface |
| --- | --- |
| HTTP server | `serve` / `route` / `reply` |
| App structure | `cast` per route, `need … from ./lib/…` |
| JSON | types that `can Json` |
| Database | `cast Database` → `Db.connect`, `db.execute`, `db.query` |
| Auth | `request.who` passed into route casts |
| Secrets | `env.get` / `env.required` |

Integrations like Stripe stay as riffs — this app does not pull them in.

## Prerequisites

Build the Vaab CLI from the sibling checkout:

```sh
cargo build -p vaab-cli --manifest-path ../vaab/Cargo.toml
```

## Run

```sh
# terminal 1 — API (runs vaab gather, then serve)
./scripts/serve.sh

# terminal 2 — static UI
python3 -m http.server 5173 --directory web
```

Open http://127.0.0.1:5173

Demo login is baked into the UI (user `ada` / `ada@example.com` signed with
`AUTH_SECRET=dev`). Mint another token with:

```sh
./scripts/mint-token.sh ada ada@example.com
```

## Layout

```
backend/
  main.vaab              thin serve block + need imports
  riff                   app manifest
  needed.lock            generated by vaab gather
  lib/
    errors/              ApiError, AuthError, …
    models/              User, Task, NewTask, …
    database/            cast Database
    auth/                cast Auth
    routes/
      health/            cast HealthRoute
      me/                cast MeRoute
      tasks/             cast TasksRoute
      quote/             cast QuoteRoute
web/                     static frontend
scripts/                 serve + token helpers
data/                    SQLite file (created on first request)
```

The same structure lives in the Vaab repo as `examples/apps/tasks/`. The single-file
CI example is `examples/15_first_class_app.vaab`.
